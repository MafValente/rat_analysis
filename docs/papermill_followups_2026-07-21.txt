Papermill / notebook follow-ups
Date: 2026-07-21

Context
- True notebook execution for `notebooks/ASD/02_daily_animal_review.ipynb` is running through papermill.
- Current warnings are not blocking local execution, but they should be cleaned up to avoid future breakage and reduce noise.

1. MissingIDFieldWarning from nbformat
Warning
- `MissingIDFieldWarning: Cell is missing an id field, this will become a hard error in future nbformat versions.`

Why it matters
- Newer notebook tooling is getting stricter about every cell having an `id`.
- Right now nbformat is auto-fixing some notebooks, but that may stop working.

What to do
- Normalize notebook JSON so every cell has an `id`.
- Do this first for:
  - `notebooks/ASD/02_daily_animal_review.ipynb`
- Then consider doing it for the other active notebooks that may be used with papermill.

Safe process
- Before normalization:
  - run `python scripts/check_notebook_markdown_drift.py notebooks/ASD/02_daily_animal_review.ipynb`
- Normalize the notebook in a way that only adds missing cell ids.
- After normalization:
  - rerun `python scripts/check_notebook_markdown_drift.py notebooks/ASD/02_daily_animal_review.ipynb`
  - inspect `git diff -- notebooks/ASD/02_daily_animal_review.ipynb`
- Goal:
  - no markdown/title/comment drift
  - only metadata/cell-id level changes unless intentionally editing a code cell

Possible implementation options
- Use nbformat normalization if available in the environment.
- Or write a tiny repo script that:
  - loads the notebook JSON
  - adds ids only to cells missing them
  - writes the notebook back without changing markdown source text

2. IPKernelApp TCP without encryption warning
Warning
- `Kernel is running over TCP without encryption. All communication (including code and outputs) is sent in plain text...`

Why it matters
- On a local single-user laptop, this is usually low risk and mostly noise.
- On shared machines or remote hosts, it is more important.

Current interpretation
- For current local papermill runs, treat this as non-blocking.

What to do
- Check whether papermill / jupyter can be configured to use a local IPC transport instead of TCP for this workflow.
- If not worth the complexity for local runs, document that this warning is acceptable on this machine and revisit only if execution moves to a shared environment.

Possible investigation
- Look into nbclient / jupyter_client kernel manager transport options.
- Check whether the launcher can explicitly prefer IPC on macOS in this environment.
